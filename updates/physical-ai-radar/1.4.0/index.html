claim-audit worksheet for recently published numeric claims (RA-01)

Adds python3 -m pairadar.claims, an offline, read-only command for the RA-01 claim review. It reads the published JSON Feed store (radar/feed.json by default). For each figure in the items[]._radar entries within the chosen window, it prints one row of a deterministic Markdown review sheet. The columns are #, day, evidence, claim, status, context, source and an empty review cell. Each status comes from distill.number_context applied to the stored text: - quoted: the figure was found in the stored excerpt. - title: the figure was found only in the title. - no-excerpt: the stored excerpt is empty, as it is for baseline entries. - unlocated: the figure is not in the stored title or truncated excerpt. Check the original source first. The reference day is the newest valid entry date, not the system clock. The header gives the store path, reference day, days, total figures T, rows shown S and skipped entries K. A whole-window status-count line always appears. When the sheet is capped, a line gives the number of hidden unlocated and no-excerpt figures and a --limit T rerun value. Items that are not objects, lack a _radar dict or have a non-canonical date are skipped and counted. Store problems (missing, unreadable or invalid JSON, wrong shape or version, no dated entries) exit 2 with one 'claims: ' stderr line and no traceback. Use it

Prerequisites: run from the repository root with Python 3 (the controller used 3.12). No network access or extra packages are needed.

1. Build a SYNTHETIC sample store. The data below is labeled and invented, not real radar data:

python3 - <<'EOF'
import json
from pairadar import feeds
from pairadar.config import Item
# SYNTHETIC example entry for trying the tool
item = Item(id="synthetic-1", title="Synthetic gripper reaches 92% success", url="https://example.org/synthetic-1", publisher="Example Lab", source_id="example", evidence="M", published="2026-09-29", summary="Synthetic summary: the gripper reached 92% success over 40 trials.", numbers=["92%", "40"])
store = {"version": feeds.JSON_FEED_VERSION, "items": [{"_radar": feeds.record(item, "2026-09-30", "2026-09-30 06:00 UTC")}]}
with open("/tmp/claims-sample.json", "w", encoding="utf-8") as fh:
    json.dump(store, fh)
EOF

2. Run the audit on the sample:

python3 -m pairadar.claims --store /tmp/claims-sample.json --days 7 --limit 30

3. For the real review, use the published store:

python3 -m pairadar.claims --days 7 --limit 30 > /tmp/claim-review.md

Options: --days takes 1 to 30 and --limit takes 1 or more. Invalid values give an argparse usage error with exit 2.

4. Open /tmp/claim-review.md and check the header (reference day, T, S, K) and the whole-window status line. If the sheet says 'Rerun with --limit T', rerun with that value.

5. Open each source link, starting with the unlocated and no-excerpt rows. Fill in the review column with the date, unit, population and limitations you checked.

Run the feature tests with: python3 -m unittest tests.test_feature_02985cec3631

Scope

Scope: - The tool reads only the radar/feed.json store format. It does not audit data/baseline.json or snapshots, fetch original sources, write correction records or produce JSON or CSV. - The issue #73 EgoScale figure (44k vs 20,854 hours) still needs a maintainer data correction. What a status means: - The store keeps only the title and a truncated excerpt, so unlocated means the figure is not in that stored text. It does not mean the claim is unsupported. - No status checks the date, unit, population or correctness of a claim. Context cells: - The context is exactly the distill.number_context output. The tests check that it equals that output and contains the figure. - The tests do not check that the context is a verbatim substring of the stored title or excerpt. number_context joins words with single spaces, so a clause that crossed a line break or repeated whitespace can differ from the raw stored text. Other behavior: - Entries with non-canonical dates, items without _radar and non-object items are skipped and counted, not repaired. - Non-string text fields are shown as empty. - The pipeline limits the store to 30 days and 100 entries. Evidence: - All test fixtures are synthetic and labeled. The passing controller checks cover the behavior on those fixtures plus the existing rerender and the full 469-test suite. They do not show accuracy on real published claims. - This is a CLI with Markdown output. No browser or visual review of this feature was done, and none applies.
