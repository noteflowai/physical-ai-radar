score keyword lane classification against a labeled shortlist

python3 -m pairadar.lanes has a new --labels PATH option. It compares the keyword lane classifier with a hand-labeled JSON file. For each entry it scores title + '. ' + summary using ranked_lanes, whose top lane is the one distill.classify picks. It then applies the existing thin/ambiguous rules. Those rules now live in a flag_reasons helper that inspect() also calls. The command prints a JSON report with: - labels: the file's basename only - labeled and margin - agreement for all, confident (unflagged) and flagged entries, each as n, agree and rate (rate is null when n is 0) - disagreements in input order, each with id (null when absent), title, label, predicted, reasons, best and runner_up A disagreement with reasons [] is a confident misfile that the flags missed. The whole file is validated before anything is scored. Invalid input exits 2 with one 'lanes: ' stderr line and empty stdout. This covers an unreadable file, invalid JSON or non-UTF-8 text, no items list, a non-object entry, an empty or non-string title or lane, a non-string id or summary, an unknown lane (the valid ids are listed), and combining --labels with --latest or --fail-on-suspicious. In labels mode the exit code is 0 whenever a report is printed. docs/METHODOLOGY.md section 9 documents the format and its limits. The controller ran the checks, not me. In the pre-feature run, 8 of the 10 feature tests errored because argparse rejected --labels. On candidate c109acf the controller ran python -m pairadar --rerender --no-readme (exit 0), the 10 feature tests (all passed) and the full unittest suite (446 tests, OK).

Use it

Prerequisites: a checkout of this repository, Python 3.12 (the version in the controller's image), no extra packages. Run from the repository root.

1. List the valid lane ids:
python3 -c "from pairadar.config import load_config; print(', '.join(l['id'] for l in load_config().lanes))"

2. Create a SYNTHETIC sample file. The lane values are placeholders, not real human judgments. Replace them with your own labels:
python3 - <<'EOF'
import json
from pairadar.config import load_config
lanes = [l["id"] for l in load_config().lanes]
items = [
    {"id": "s1", "title": "Control barrier function safety filter with runtime monitor", "summary": "Synthetic example.", "lane": lanes[0]},
    {"title": "Untitled robotics note", "lane": lanes[-1]},
]
with open("my-labels.json", "w", encoding="utf-8") as fh:
    json.dump({"items": items}, fh, ensure_ascii=False, indent=2)
EOF

3. Score it:
python3 -m pairadar.lanes --labels my-labels.json --margin 0.35

4. Read agreement.all.rate, then compare agreement.confident with agreement.flagged. Look first at disagreements whose reasons is [], because the flags missed those. Edit data/taxonomy.json and re-run on the same file to compare before and after.

5. Error example:
python3 -m pairadar.lanes --labels missing.json
This exits 2 and prints a single 'lanes: cannot read missing.json: ...' line.

Tests: python3 -m unittest discover -s tests -p test_feature_5621e4c46330.py

Scope

Scope: - One input format (a JSON items list) and one entry point. --labels combines only with --margin. - There is no threshold-based failure exit, CSV input, automatic taxonomy editing or model/provider call. - Classification and scoring are unchanged. What the numbers mean: - Labels come from the user. - The test fixtures and the usage sample are synthetic and labeled as such. - The passing tests show that the counts, ordering and error handling match hand-computed expectations. They do not show broad classifier accuracy. - Agreement on a small labeled set measures the current taxonomy on those items only. It is not general accuracy, and the margin is not calibrated. - Keep the labeled set separate from the examples used to tune keywords. Verification gaps: - This is a CLI-only feature. No browser or visual review of it was done, and I did not check whether the full suite includes browser or showcase tests. - An earlier review flagged unrelated banner SVG coordinate changes and a CHANGELOG file-list claim. The controller receipts do not include the final diff's file list, and I could not inspect it. So this text makes no claim about which files the commit touches beyond the lanes feature. - The rerender check exiting 0 does not prove that assets are unchanged. - Issue #73 is not addressed.

Upgrade and rollback

Additive. Without --labels, the existing command and its --latest, --margin and --fail-on-suspicious options keep their output and exit codes. The --latest default now resolves internally to the same radar/latest.json path. inspect() now calls the extracted flag_reasons helper, which uses the same rules. Label files are only read, and the feature adds no stored data or schema. To roll back, revert the feature commit. Label files are user-owned and stay intact. Before releasing, confirm the commit's file list matches the lanes feature (see limitations).
