fix: label README baseline fallback on days with no live picks

On a day with no live picks, the README radar block in all three languages (README.md, README.en.md, README.ja.md) now explains the empty day the same way the frozen daily page does. readme_block in pairadar/render.py keeps the existing day heading and generated/window line. After them it adds the localized no-items sentence as a Markdown quote, then a bold label from the existing glossary baseline string, then the curated baseline table, evidence legend, reasons and links. Before this change, the baseline entries appeared under the day's heading, ranked and in the pick column, with no explanation. If there are no picks and no baseline, the block shows the no-items line and an empty table header without raising. Days with picks keep the previous rendering. docs/METHODOLOGY.md describes the empty-day README behavior. Checks run by the controller on candidate dfb3436 (base 047ef4a): before the change, the new test file failed 2 of 3 tests (the empty-day label test and the nothing-at-all test), which confirms the defect. After the change, rerender exited 0, the 3 tests in tests/test_feature_b41f745004f1.py passed, and the full suite of 484 tests passed.

Use it

Prerequisites: a checkout of this repository, Python 3 and the repository root as the working directory. The pipeline uses only the standard library. No sample input file is needed: the feature tests build a synthetic in-memory ctx with an empty picked list and use the repository's curated baseline. These are the same commands the controller ran:

python -m pairadar --rerender --no-readme
python -m unittest discover -s tests -p test_feature_b41f745004f1.py
python -m unittest discover -s tests

The first command re-renders the current published snapshot without touching the README files. In the controller run it reported 8 published picks for 2026-10-04, so it exercises the normal-day path. The second command checks the empty-day behavior in zh, en and ja. In each language, the block must contain the line '> ' plus the glossary no_items sentence after the generated/window line, then '**' plus the glossary baseline label before the table header. Every baseline title must still be in the table. The command also checks that a day with picks has neither line, and that a day with no picks and no baseline renders without error. On a real empty day, the normal scheduled run regenerates the README blocks with this labelling.

Scope

Only the README radar block's empty-picks case changed. These are unchanged: the landing-site cards (pairadar/site.py), the banner, the charts, partly filled days (fewer picks than the maximum), selection thresholds, per-lane caps and the 30-day duplicate window. The wording reuses the existing no_items and baseline glossary strings, and no new translations were added. The evidence is string assertions on synthetic ctx data and a rerender of a snapshot with picks. The controller's receipts do not include a live empty day, and no browser or visual review of how GitHub renders the new quote and label was done for this feature. Passing tests show the specified structure, not the readability of the rendered page. The normal-day test passed both before and after the change, but byte-identity was only checked for the cases the tests cover. The issue #73 EgoScale figure in data/baseline.json is still uncorrected and is out of scope for this lane.

Upgrade and rollback

There are no data, schema, configuration or dependency changes. After the upgrade, the next scheduled run or rerender that writes READMEs regenerates the radar blocks between the existing RADAR markers. Saved snapshots, feeds, weekly pages and frozen daily pages are not rewritten. To roll back, revert commit dfb3436. The next README-writing run then restores the previous unlabeled baseline fallback. Nothing else needs to be migrated or cleaned up.
