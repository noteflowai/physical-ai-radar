test: EA-02 regression corpus that pins how the diff gate handles missing evidence

Commit b0de9ac adds tests/test_feature_cb4fe5a9ab91.py, a synthetic regression corpus for EA-02. Every case id carries a synthetic label. Each case loads its inputs with load_results, runs diff and checks the gate outcome through evidence.diff_passed and the render_markdown headings. Control and added-check cases pass. Removed checks, fewer Inspect epochs at an unchanged pass rate, a JUnit pass-to-skipped change with no other difference, and incomplete baseline or current runs all fail the gate. Malformed records, duplicate IDs and non-comparable runs (different task or format) raise ValueError. An invariant test checks that no lost-evidence case passes. The corpus exposed one defect, fixed in src/evalarc/results_diff.py. Before the fix, a repeated Inspect sample ID loaded as extra attempts and could pass the gate when any copy had a null, boolean, string or other non-integer epoch, or when integer and missing epochs were mixed. Those logs now raise ValueError with the message duplicate sample '<id>' without a valid epoch (got ...). Legacy behavior is unchanged: if every copy of an ID omits the epoch key, the copies still load as attempts, and a single sample with no epoch still loads. The controller ran the checks. I did not run them. Before the fix, the controller's acceptance run of the new test file exited 1 with 8 failed and 20 passed. All 8 failures were in the duplicate-epoch cases. Scope

All corpus fixtures are synthetic. They pin EvalArc's own classification rules and say nothing about real Inspect, promptfoo or JUnit exports (EA-01), reviewer timing (EA-03), false-alarm rates or broad accuracy. Passing tests do not show that every malformed real-world log is caught. Known gaps: - Inspect copies of one sample ID that all omit the epoch key still load as separate attempts, so EvalArc cannot detect duplicated or lost coverage in those logs. - A promptfoo duplicate whose testIdx was edited to a distinct value still loads as a separate attempt. Kind names, schema evalarc.results-diff.v1, CLI flags and exit codes are unchanged. This feature changes no UI. The controller ran scripts/check_site.cjs, which exited 0. Its log shows the existing showcase/browser regression checks at 1440, 390 and 320 px widths, plus offline variants. Those checks cover existing pages, not this change. I reviewed no screenshots. The controller executed all checks. I ran no commands. The manual usage snippet was not executed by anyone. Upgrade and rollback

No data, schema or configuration migration is needed. Behavior changes only for Inspect logs that repeat a sample ID where a copy has a null, boolean, string or other non-integer epoch, or where integer and missing epochs are mixed. Those logs now raise ValueError, and the diff CLI treats them as unusable input (exit 2). Before, the copies counted as extra attempts and could pass the gate. These logs load as before: - logs with unique sample IDs - logs whose repeated IDs each carry distinct integer epochs - logs whose repeated copies all omit the epoch key If a CI job starts exiting 2 with this message, regenerate the log or rerun the evaluation so that each repeated sample has its own integer epoch. Do not edit epochs by hand to force a pass. To roll back, revert commit b0de9ac. That restores the earlier permissive loading. Existing reports and saved results are not affected.
