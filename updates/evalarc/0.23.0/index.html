show the per-finding "Why the gate failed" explanation in the diff index.html

When a diff has at least one blocking change, evalarc diff BASELINE CURRENT --output DIR now writes a 'Why the gate failed' section into DIR/index.html. This is the report the CLI prints as 'Report:'. The section comes after the Changed checks table and before the remaining sections. The section contains: - The numeric threshold sentence, worded as in summary.md. - A table with the columns Finding, Case / check, Baseline, Current and Failing attempt. - A metadata line with each input's file name and a 12-character sha256 prefix. Table cells: - Finding shows the kind, plus '(within noise)' when flagged. It is rendered as a ✗ tone label, so it does not rely on color. - Failing attempt shows the first failing current attempt's value and evidence, each clipped to 120 characters. - Removed checks show the baseline attempt, labelled 'not recorded in the current run; baseline:'. - Rows without detail show 'no attempt detail recorded'. Every value is HTML-escaped. The HTML table lists every blocking row with no limit. summary.md and index.html are both built from the shared helper _blocking_rows. When nothing blocks, the section is not written. The gate logic, exit codes and the diff.json schema are unchanged.

Use it

Prerequisites: a checkout of this repository at commit 7f29db9, with the evalarc command installed from it. The two input files below are bundled example files that ship in the checkout, so you do not need to create any input.

# Blocking diff. Expected exit 1.
evalarc diff examples/results-diff/inspect/baseline.json examples/results-diff/inspect/current.json --output inspect-diff; echo exit=$?
grep -c 'Why the gate failed' inspect-diff/index.html   # nonzero
# Open inspect-diff/index.html in a browser and scroll below Changed checks.
# Expected row (from the acceptance criteria):
# ✗ less reliable (within noise) | cancel-pending / match | 2/2 | 1/2 | value I · evidence cancel:1006:queued

# Self-comparison. Expected exit 0, and the section is absent.
evalarc diff examples/results-diff/inspect/current.json examples/results-diff/inspect/current.json --output self-diff; echo exit=$?
grep -c 'Why the gate failed' self-diff/index.html   # prints 0

# Feature tests. The escaping test appends labelled synthetic rows.
python -m pytest -q tests/test_feature_e5db40f1ad73.py

Upgrade and rollback

Upgrade the package and rerun evalarc diff to regenerate index.html. Input formats, diff.json and exit codes are unchanged. summary.md is built by the same rules as before. Existing report folders are not rewritten. To roll back, install the previous version and regenerate the reports. You can regenerate from the input copies kept in each report folder, so no data is lost. Pipelines that parse index.html should allow for the new section, which appears only when the gate has blocking findings.
